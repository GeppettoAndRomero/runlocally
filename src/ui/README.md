# Shared UI components

Import individual components from this directory. Load `../styles/tokens.css`, then `../styles/base.css`, then `components.css` in the host layout. The components have no stylesheet imports and do not mount themselves on a page.

- `AppButton`: `variant` is `primary`, `secondary`, or `ghost`; `type` defaults to `button`. Disabled buttons retain native disabled behavior. Buttons have a 44px minimum height and a visible keyboard focus outline.
- `AppCard`: optional h2 title and description precede the children. Workbench result items use h3 beneath the card title.
- `AppField`: controlled `value` and `onChange`; the label, error and help text are connected to the input through `for` and `aria-describedby`. `locale` selects the required marker. Inputs and selects have a 44px minimum height; textareas retain an 80px minimum. Keyboard focus has a visible outline.
- `WorkbenchFeedback`: `Alert` and `Status` preserve one role per message and hide SVG decoration from assistive technology. `Status` can show native extract progress for a known positive total; its spinner stops under reduced motion. Shared styling lives in `components.css`.
- `AppModal`: `isOpen`, `onClose`, title and children. The close button, backdrop and Escape call `onClose`. Its effect restores the prior body overflow and removes the key listener.
- `ThemeToggle`: remains available as a standalone component but is not mounted in the product pages. It reads and writes `runlocally-theme`, updates `data-theme`, follows system preference in its `auto` state, and removes its listener on unmount. The shared CSS follows the operating system setting regardless of that attribute or stored value.
- `GlobalDropZone`: listens on `document.body` for drag and drop, on `document` for pasted files, and on `window` for `filesProcessed`. It emits `filesDropped` as `CustomEvent<File[]>`. The Workbench host sets `window.__toolReady` after installing its listener, acknowledges each `filesDropped` notification with `filesProcessed`, and clears ready and listeners on departure. This component does not set ready. Workbench accepts one archive per notification; the shared drop component can still emit multiple files. Folder entries are read through all batches and nested levels. When folder scanning fails or yields no files, available flat files are used. If a browser does not allow `webkitRelativePath` assignment, only the filename remains. Unmount removes listeners and suppresses results from pending scans. Folder support here does not itself add a create screen.
- `InstallPrompt`: only shows after `beforeinstallprompt`; the browser must provide that event. The component does not promise installation or offline support. It stores only display preferences under the `runlocally-install-prompt-*` keys. It removes the listener on unmount.

`src/ui/input-state-copy.ts` eagerly collects only the finite `inputState` section from registered locale dictionaries, checking every key for nonblank text. The existing `src/i18n/ui.ts` export continues to expose workbench and shared text separately.

All components accept a registered `Locale` from `src/i18n/locales.ts`. Display names and locale metadata come from that registry. UI and page dictionaries are gathered separately from registered locale directories. See [I18N.md](../../docs/I18N.md) for adding a locale. Omitting `locale` keeps the existing English fallback, derived from that locale list. Shared component and Workbench text live in `src/i18n/<locale>/ui.ts` and must satisfy the finite shared and workbench keys in `UiStrings` from `src/i18n/types.ts`. `src/i18n/ui.ts` aggregates those dictionaries by locale without importing page content. Page content lives separately in `src/i18n/<locale>/pages.ts`. Component tests use jsdom; they do not establish browser installation availability or visual appearance.

## Changes from the source components

| Component | Display or styling difference | Reason |
| --- | --- | --- |
| `AppButton` | Button element, variant classes, and disabled styling are retained. The required button rules are copied into `components.css`; unrelated form and page rules are omitted. Minimum height is 44px. | Keep the button's appearance and a consistent control size without loading the source application's whole stylesheet. |
| `AppCard` | Header, title, description, and child order are retained. Card rules are included in `components.css`. | Preserve the card structure and its visual dependencies. |
| `AppField` | Error and help text render together. Both IDs are listed in `aria-describedby`. The field rules include a 44px control minimum, 80px textarea minimum, and keyboard focus outline. | Keep guidance available to sighted and assistive technology users, with visible focus. |
| `AppModal` | The backdrop, dialog, header, close button, and content remain. Inline layout styles moved to `components.css`; the inline hover handlers and animations were removed. The dialog now has a role, modal state, and title label. | Keep layout styles in one place and expose the dialog structure to assistive technology. |
| `ThemeToggle` | The icon and text button remain in the component library but are not mounted on product pages. Inline base and hover styles moved to `components.css`; the hover transform, shadow, and icon sizing were omitted. Its attribute and storage updates do not change shared CSS colors. | Keep the component contract while product colors follow the operating system setting. |
| `GlobalDropZone` | The full-screen, non-intercepting overlay remains, but its inner bordered panel was removed. Feedback decoration, heading, and supporting text remain inside the overlay; inline fade and spinner animations were omitted. | Keep the drop feedback while using a smaller shared CSS surface. |
| `InstallPrompt` | Banner and footer modes remain, but the nested banner layout, phone icons, pulse and slide animations, and inline hover styles were removed. The banner uses a named region; both modes use classes in `components.css`. | Keep the event-driven install action and dismissal controls without carrying over decorative effects or source-specific layout. |

`tokens.css` defines light colors at `:root` and dark overrides under `prefers-color-scheme: dark`. It separates link, button, error badge, and control border colors. `base.css` sets the 72rem explanation width and 44px minimum for controls, excluding ordinary links; it also keeps reduced motion and session explanation rules. `components.css` contains the shared component selectors. `tests/unit/tokens-contrast.test.ts` checks token contrast in both themes for text, links, buttons, errors, borders, and focus. Folder scans and emitted file notifications are independent: a `filesProcessed` event acknowledges a previously emitted notification and does not cancel a scan still in progress.

## Browser check

Browser verification should cover Japanese and English pages at 360px, 768px, and 1280px in Chromium, Firefox, and WebKit. Check an initial light and dark context, a live operating system color change without reload, and a stored `runlocally-theme` value opposed to the operating system setting. Inspect computed body colors and root `color-scheme`, control minimum heights and actual bounds, inline link height, keyboard focus, reduced motion, and explanation visibility after input and Reset. Standalone display width requires a context where `matchMedia('(display-mode: standalone)').matches` is true. A standalone mount of `ThemeToggle` continues to update its attribute and storage value without changing the shared CSS theme.
