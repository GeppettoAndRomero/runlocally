# 言語と公開ページ

## 言語の追加

1. 需要の証拠を確認する。
2. ネイティブレビュー体制を用意する。
3. `src/i18n/locales.ts` に `code`、`default`、`hreflang`、`ogLocale`、`name` を登録する。既定言語は一つにする。
4. `src/i18n/<locale>/pages.ts` と `src/i18n/<locale>/ui.ts` を追加し、`src/i18n/hub.ts`、`src/i18n/about.ts` と `src/i18n/image-page.ts` にも同じ言語のハブ・about・画像本文を登録する。すべての公開操作の本文と UI キーを埋める。共通 UI キーにはフッターのセキュリティリンクも含む。外枠の文言は `chrome` に置き、`ChromeStringKey` の有限キーと英語参照に対する各言語の欠落・空文字を検査する。従来の `ui` export は `shared` と `workbench`、外枠用の `chromeUi` export は `chrome` を公開する。辞書集約は登録済み言語の両ファイルが欠けるとビルドで失敗する。`hub.ts` と `image-page.ts` は登録言語と必須キーの欠落・空文字を検査する。about は AboutContent の14キー（手順は4項目、他は文字列）を登録し、validateAbouts が厳密な言語・キー集合、非空と metadata 上限を検査する。ハブは既存8キーを維持し、辞書検証時にも共通の `checkMetadataLength()` で title 60・description 120 Unicode code points 以下を検査する。未登録ディレクトリは公開されない。
5. 生成 HTML、言語選択、相互 hreflang、sitemap を確認する。URL は既定言語のみ prefix を省き、英語ページを `x-default` とする。

ページは `LOCALES` と `SITE_PAGES` から生成する。現在は索引対象16ページ（ハブ2・about 2・ZIP 12）に、noindex の画像2ページを加えた SITE 18ページを生成する。本文と head は初期 HTML に含まれ、ZIP 内で操作や言語を切り替えると同梱辞書を使って外枠のリンク・現在ページ表示も更新する。切り替えは現在の File、一覧、選択、設定、結果、実行中の処理を保持する。戻る・進むは操作と言語を復元するが、過去のセッション状態へは巻き戻さない。再読み込みや別タブをまたぐ File 保持はしない。

`src/seo/url-model.ts` が URL 規則を定義し、`src/seo/page.ts` は公開ページの生成・判定をこのモデルへ委譲する。ハブと about の生成、公開型・公開判定、head の接続は完了している。

- about は日本語 `/about/`、英語 `/en/about/`。自己 canonical、ja/en と英語 x-default を持ち、indexable な WebPage と BreadcrumbList を `@graph` で分けて出力する。
- ハブは日本語 `/`、英語 `/en/`。ZIP トップは `/zip/`、`/en/zip/`。

JSON-LD はハブだけが単独の WebSite（`sameAs` は package.json の公開製品 repository）を出力し、パンくずを持たない。他のページは `@graph` の第1ノードが ZIP・画像の SoftwareApplication または about の WebPage、第2ノードが BreadcrumbList。パンくずは同じ言語のホーム → ZIP top → 操作、ホーム → ZIP top、ホーム → about、ホーム → 画像変換の階層で、正規 URL と1からの position を使う。名称は既存辞書の chrome.home、ZIP top の h1、現在ページの h1 を使う。`headData()` と `safeJsonLd()` を静的 HTML と ZIP の `displayPage()` 更新で共有する。自己申告の aggregateRating・FAQPage・HowTo は出力せず、リッチリザルトの表示を完了条件にしない。

- ZIP 操作は `/zip/<slug>/`、`/en/zip/<slug>/`。操作部分は `AVAILABLE_OPS` だけから導出する。
- `SitePage` は `PublicPage` と `UNLISTED_PAGES` の image を含む。画像ページは `/image/`、`/en/image/` で、noindex とし sitemap には掲載しない。`pagePath()`・`pageUrl()`・`sitePageFromPath()` が扱い、PUBLIC／ZIP の判定からは除外する。
- `PublicPage` はハブ・about と ZIP ページ、`ZipPage` は ZIP top と公開5操作だけを含む。公開側の `pagePath()`、`pageUrl()`、`publicPageFromPath()`、`publicPageFromUrl()` はハブ・about を含む。ZIP 専用の `zipPageFromPath()` はハブ・about を拒否する。path 判定は正規の pathname との完全一致、URL 判定は正規の公開 URL との完全一致を要求する。
- 短い slug は `ZIP_SLUGS` に定義し、全11操作の `OPS.slug` がこれを参照する。公開するのは `AVAILABLE_OPS` の5操作（browse・extract・remove・fix-names・create）だけである。

旧操作 URL は Pages Functions が410を返す。ただし後継の公開ページがある5機能（閲覧・取り出し・削除・文字化け修復・作成）の旧文書パス（旧無印は英語、`/ja/` は日本語。末尾スラッシュの有無、GET/HEAD のみ、query なし）は同じ言語の後継ページへ301転送する（20パス、`functions/_middleware.js` の `LEGACY_DOCUMENT_REDIRECTS`）。`/en/<slug>/`・他の旧言語・`sw.js`・アセット・子パスと、後継のない旧ページは410のまま。例外は旧 `/sitemap.xml` で、現行の `/sitemap-index.xml` へ301転送する。sitemap は PUBLIC の索引対象16ページ、PWA precache は SITE の生成18ページから導出し、単体テストでそれぞれ照合する。これらに属さない唯一の生成 HTML が `404.html`（`src/pages/404.astro`、辞書は `src/i18n/not-found.ts`）で、未定義 URL に対してホストが404で返す。日英の見出し・案内・ハブと ZIP へのリンクを1文書に持ち、noindex で canonical・hreflang・JSON-LD を持たず、precache にも含めない。自動検証の範囲と端末での確認手順は [PWA.md](PWA.md) を参照する。

Workbench、ZIP 本文の `pageContent()`、動的表示の `displayPage()` は `ZipPage` のみを受け取る。Workbench のクリックと履歴判定は `zipPageFromPath()` を使う。上の File・一覧・結果保持は ZIP 内の遷移に適用される。ハブ・about・画像ページへの通常遷移には適用しない。about と画像ページの言語切替も通常遷移する。フッターの about は常に同言語の通常リンクで、ZIP の言語切替・履歴復元では html.lang に連動する CSS が表示を更新する。ブランドリンクは現在の言語のハブを指し、通常遷移する。ZIP の操作ナビは ZIP ページだけに表示する。

File が受理されると `html[data-session="open"]` により説明文を隠す。リセット後は現在の操作と言語の説明文を表示する。操作画面と共通フッターは隠さない。

作成の文言は `createUi` として集約し、既存の `shared`／`workbench` のキーとは分ける。作成のメニュー文言とページ本文も公開対象に含む。未公開操作はパネル登録だけではメニュー・本文・URL を公開しない。

## 操作の公開

`src/i18n/ops.ts` へ台帳登録し、入力・出力型、形式別ガード、controller の実行と終了処理、UI、本文辞書、アクセシブル名、テストを揃える。その後 `available` を変更し、ページ、タブ、hreflang、sitemap、HTML 件数を確認する。エンジン API の存在だけでは公開しない。

## 検証

`npm run ci` を実行し、生成 HTML の18 URL と `404.html`（計19 HTML）、sitemap の索引対象16 URL をそれぞれ照合する。日英ハブの画像カードから同じ言語の変換画面への到達、ZIP カードから公開5操作への直リンク、ZIP と画像の両方を案内する title・description・h1・lead、OG と WebSite JSON-LD（`name` はサイト名 `runlocally`、`alternateName` が h1）の整合、文字数の境界・空文字を検査する。404 文書の内容・未定義 URL の404応答・旧 sitemap の301は `tests/unit/not-found-page.test.ts` と `tests/e2e/seo-discovery.spec.ts` が検査する。ハブの本文・リンクと ZIP ページの直接訪問、言語・操作・履歴の切り替え、File と結果の保持、入力形式による補正、説明文の再表示、head を確認する。`tests/unit/about.c370-about.test.ts` は辞書・URL 境界・生成本文と metadata・全 SITE フッター・sitemap／precache／build meta と欠落・重複拒否を検査する。`tests/e2e/about.c370-about.spec.ts` は通常遷移・言語と履歴・JS 無効・通信・Functions 応答、`tests/e2e/about-pwa.c370-about.spec.ts` は直訪問の保存後オフラインと人工旧 SW 移行を検査する。Functions を含むローカル確認には [PWA.md](PWA.md) の Wrangler Pages 手順を使う。

画像本文は `image-page.ts`、変換 UI は `image-tool.ts` が所有する。旧 `image-soon.ts` は過去の準備中段階の辞書として残し、製品ページと SEO からは参照しない。画像ページの言語切替は通常遷移で、ZIP 内遷移の状態保持は約束しない。

### 入力形式確認の辞書

`src/i18n/image-capability.ts` は入力形式確認の見出し、形式名、確認中・可否、
HEIC／HEIF の処理経路と保証範囲の注記を所有する。言語追加時は登録言語と
キー集合を一致させ、空文字禁止と Unicode コードポイント数の上限を検証する。
既存の画像変換辞書とは独立したキー・上限のテストを維持する。

### 画像変換の進捗辞書

`src/i18n/image-progress.ts` は全体バーのラベル、終了枚数の補間文、
処理中ファイルのラベル、`ImageStage` の閉集合に対応する段階名を所有する。
既存の画像変換・形式確認辞書のキー集合は変更しない。言語追加時は登録言語、
厳密なキー集合、空文字禁止、Unicode コードポイント数の上限に加え、
枚数表示に `{done}` と `{total}` が各一つ含まれることを検証する。

JSON-LD の追加検証は `tests/unit/jsonld-breadcrumb.test.ts` と `tests/e2e/jsonld-breadcrumb.spec.ts`。全 SITE ページの階層・役割・sameAs・エスケープ、静的 HTML と ZIP の操作・言語切替および戻る／進む後の一致を確認する。
